# Contributing

Thanks for contributing to Claude Prompt Architect.

## Good contribution areas

- improve prompt architecture
- add engineering scenarios
- improve correction / continuation handling
- add framework-specific examples
- improve anti-hallucination safeguards
- improve verification/reporting requirements
- improve documentation

## Guidelines

1. Keep examples generic and safe for public use.
2. Do not add proprietary project code, internal URLs, credentials, tokens, or private hostnames.
3. Preserve exact technical identifiers in examples where they are intentionally part of the scenario.
4. Prefer repository-grounded behavior over invented assumptions.
5. Avoid adding generic boilerplate unless it improves engineering execution.
6. Keep changes scoped and explain why they are useful.

## Pull requests

A pull request should explain:

- what problem it solves,
- why the change belongs in the prompt architecture,
- which workflows are affected,
- whether examples or documentation were updated.
