# Quality Checklist

Before delivering a prompt, check:

- Coverage: every explicit requirement is represented.
- Intent: the requested engineering action is clear.
- Evidence: facts, report claims, and assumptions remain distinct.
- Fidelity: identifiers, APIs, DTOs, keys, casing, and literals remain exact.
- Architecture: relevant prompt sections are represented.
- Diagnosis: bugs require root-cause tracing.
- Existing work: working implementation is not unnecessarily redone.
- References: named references have a clear purpose.
- Scope: unrelated changes are discouraged.
- Reuse: existing architecture is preferred over duplication.
- Domain: framework-specific instructions match known context.
- Verification: acceptance criteria and relevant checks are explicit.
- Reporting: the downstream agent must report actual results.
- Clarity: avoid unnecessary questions, repetition, and inflated urgency.
